# 功能规格说明：Sub2API 实时分组监控

**功能标识**: `sub2api-monitor`
**功能目录**: `specs/sub2api-monitor`
**创建日期**: 2026-07-16
**状态**: 认证修订 v2 已确认，实施中
**原始需求**: 开发基于 sub2api API 的 macOS 桌面实时分组监控工具，支持置顶窗口、气泡、菜单栏展示，以及聚合账号分组切换。
**任务通道**: controlled
**需求版本**: v1
**确认状态**: confirmed by user on 2026-07-16

## 1. 业务背景与目标

- 业务背景：用户需要同时观察多个 Sub2API 中转站的余额、分组倍率/价格和可用性，并管理自建聚合站账号的分组。
- 本次目标：交付一个 macOS 优先的 Electron MVP，支持多站配置、实时快照、紧凑窗口形态和显式确认的管理员切组。
- 非目标：不修改 Sub2API 服务端；不实现支付、账号凭证导入、批量删除、远程发布或自动切组策略。

## 2. 用户场景与验收

### 场景 1 - 监控多个中转站（优先级：P1）

描述：用户添加站点后，在一个窗口中查看每个站的余额、连接状态、分组倍率和价格摘要。

验收：

1. **Given** 至少两个已配置站点，**When** 打开主窗口或点击刷新，**Then** 每个站独立显示加载、成功、过期或失败状态，且不因单站失败阻塞其他站点。
2. **Given** 站点返回模型定价和分组倍率，**When** 快照完成，**Then** UI 显示更新时间、基础价格来源和实际倍率；缺少定价接口时明确显示“价格不可用”，不伪造价格。

### 场景 2 - 紧凑桌面形态（优先级：P1）

描述：用户可以在完整窗口、置顶浮窗、气泡和 macOS 菜单栏弹层之间切换。

验收：

1. **Given** 主窗口已启动，**When** 用户选择窗口模式，**Then** 模式切换不丢失当前快照和筛选状态。
2. **Given** 菜单栏或气泡模式，**When** 用户点击入口，**Then** 可打开摘要并进入完整窗口，关闭后焦点回到原入口。

### 场景 3 - 聚合账号切组（优先级：P1）

描述：管理员连接下，用户查看账号当前分组并发起显式切换。

验收：

1. **Given** 站点管理员凭证有效，**When** 用户选择账号和目标分组，**Then** 弹出包含旧分组、新分组和站点名称的确认界面。
2. **Given** 用户确认切组，**When** 远程更新成功，**Then** 刷新账号快照并显示成功状态；失败时保留原选择、显示错误和重试入口。
3. **Given** 用户没有管理员权限，**When** 打开账号管理，**Then** 只能查看权限错误，不出现可提交的远程写入按钮。

## 3. 事项清单

### ITEM-001：多站连接与安全配置

- 目标：添加、编辑、删除 Sub2API 站点连接，并区分普通用户读取上下文和管理员写入上下文。
- 完成结果：站点列表持久化在 macOS 安全存储中，渲染层只拿到脱敏状态和快照。
- 验收标准：无密钥进入仓库、日志、URL 或 renderer localStorage；连接校验失败能重试。
- 依赖：Electron 主进程和 preload IPC。
- 状态：confirmed

### ITEM-002：实时余额、分组倍率与价格监控

- 目标：按站点轮询并归一化 `/user/profile`、`/groups/available`、`/groups/rates` 和 `/channels/available`。
- 完成结果：站点独立显示余额、健康、更新时间、倍率和价格可用性。
- 验收标准：默认 30 秒轮询；超时、401/403、接口关闭和返回结构异常均有明确状态。
- 依赖：Sub2API 适配层和内存快照。
- 状态：confirmed

### ITEM-003：窗口、气泡和菜单栏形态

- 目标：支持完整窗口、置顶浮窗、气泡入口和 macOS 菜单栏摘要。
- 完成结果：切换形态不丢数据，紧凑尺寸下主要操作和状态可用。
- 验收标准：在受支持窗口尺寸下无溢出、遮挡或不可达操作；焦点和关闭行为可恢复。
- 依赖：Electron BrowserWindow、Tray/Menu、renderer 响应式布局。
- 状态：confirmed

### ITEM-004：管理员账号分组切换

- 目标：读取管理员账号/分组，提交显式确认的 `group_ids` 更新。
- 完成结果：成功后以服务端返回为准刷新；失败不做乐观持久化。
- 验收标准：无管理员权限不显示写入；确认框展示具体变更；请求和错误不泄漏凭证。
- 依赖：管理员 API 适配、确认对话框和刷新链路。
- 状态：confirmed

### ITEM-005：状态反馈、测试与交付闭环

- 目标：覆盖加载、空数据、成功、过期、网络错误、鉴权错误和重试。
- 完成结果：提供自动检查、可见 Electron 验证路径和中文验证报告。
- 验收标准：`npm run verify` 可执行；关键 UI 路径有截图或明确的自动化阻塞说明。
- 依赖：项目脚本和可见浏览器/桌面验证能力。
- 状态：confirmed

## 4. 业务规则与边界

- 每个站点独立轮询与失败，不允许一个站点异常覆盖其他站点状态。
- 读取接口默认使用用户上下文；管理员上下文仅用于账号/分组管理。
- 价格展示必须区分“接口未提供”“接口被禁用”和“实际没有价格”三种情况。
- 远程切组是外部写入，必须经过用户确认；不实现自动轮换或后台静默写入。
- 令牌、密码、Cookie 和完整 API 响应中的敏感字段不得进入 renderer 持久化、日志、截图或错误消息。

## 5. 异常与边界场景

- 当站点 URL 无效或超时时：保留上次成功快照，并标记 stale 与重试时间。
- 当返回 401/403 时：停止该站点轮询，提示重新配置对应上下文。
- 当 `/channels/available` 未启用时：显示倍率和余额，价格区域显示不可用原因。
- 当管理员切组失败时：不修改本地目标状态，提供重试和重新读取账号按钮。
- 当窗口缩小到紧凑尺寸时：隐藏次要价格字段，但保留余额、健康、更新时间和刷新入口。

## 6. 功能需求

- **FR-001**：站点配置、凭证分类和安全持久化必须由主进程拥有。
- **FR-002**：主进程提供带取消和超时的单站点快照请求，并以统一 DTO 发送给 renderer。
- **FR-003**：renderer 必须呈现每站 loading/empty/success/stale/error/retry 状态。
- **FR-004**：窗口模式由主进程控制，renderer 只请求模式变化，不直接调用 Electron 原生 API。
- **FR-005**：管理员切组必须先读取服务端当前账号，再提交显式确认的 `group_ids`。
- **FR-006**：轮询定时器、事件监听和窗口销毁时必须清理。

## 7. 关键对象

- **StationConfig**：站点标识、显示名、API 基址、读取上下文、管理员上下文引用和轮询设置。
- **StationSnapshot**：余额、分组、价格摘要、更新时间、健康状态、错误类型和数据新鲜度。
- **AccountGroupMutation**：站点、账号、旧分组、目标分组、确认状态和服务端结果。

## 8. 成功标准

- **SC-001**：在模拟数据下完成多站监控、模式切换和错误恢复的可见路径。
- **SC-002**：在真实 Sub2API 兼容站点上可配置读取上下文并显示余额/分组数据；价格按接口能力降级。
- **SC-003**：管理员切组请求只在确认后发出，失败可重试，且测试/日志不包含凭证。

## 9. 假设与依赖

- 假设 Sub2API 站点使用 `/api/v1` API 前缀及 Bearer 令牌机制。
- 假设用户可以提供访问令牌或通过站点登录获得令牌；本 MVP 不保存明文密码。
- 依赖 Electron 在目标 macOS 版本支持 Tray 和 `safeStorage`。

## 12. 需求修订 v2（已确认）

### 修订原因

- v1 将访问 token 和管理员 token 作为两个手工 Bearer 输入，没有覆盖站点网页登录授权。
- Sub2API 普通分组接口使用登录 JWT；普通网关 API Key 不能调用该接口。
- 管理员全分组接口支持管理员 JWT，或通过 `x-api-key` 传入管理员 API Key；v1 未区分这两种 header。

### ITEM-001-R2：统一站点认证入口

- 支持粘贴 Sub2API 登录 JWT。
- 支持打开隔离的站点登录窗口，兼容站点自身的邮箱、OAuth、Turnstile 和 2FA 流程；授权完成后加密保存 access/refresh token。
- 支持管理员 API Key，并明确使用 `x-api-key`，不把它当作 Bearer JWT。
- 普通 `sk-...` 网关 API Key 只用于模型调用，不作为控制台分组查询凭证。

### ITEM-002-R2：按登录权限查询分组

- 普通登录账号调用 `/groups/available`，展示该账号在 Sub2API 创建/绑定 API Key 时可选择的全部分组和专属倍率；不调用管理员全量接口。
- 管理员登录 JWT 或管理员 API Key 调用 `/admin/groups/all`，展示全站活跃分组，并开放账号管理。
- 应用默认使用登录 JWT 读取普通账号可用分组；管理员 JWT/API Key 作为独立可选上下文配置，用于账号管理，不把普通网关 API Key 当作分组查询凭证。

### 新增安全影响

- 远程登录窗口必须 `sandbox: true`、`nodeIntegration: false`，不挂载应用 preload。
- 授权会话使用站点独立的临时 session partition；捕获 token 后清理远程浏览数据。
- OAuth code、Turnstile token 和 2FA 输入只在站点原页面发生，AIZZZWatch 不读取或保存。网页登录账号密码可由用户主动选择加密保存；仅主进程可解密，并且只会在用户主动选择“使用保存账号密码授权”时、同源登录页已识别账号和密码输入框时填入，不自动提交。
- refresh token 由主进程加密保存，仅用于 `/auth/refresh`，失败后要求重新授权。

## 13. 上游关联诊断与自动配对 v1（已确认）

- “使用中”只表示已开启调度的我的站点账号，且它与三方站点某把上游 Key 的关系已经被精确匹配或由用户确认。
- Key 原文只允许在主进程当前刷新内做 SHA-256 指纹比对；renderer、IPC 快照和本地偏好只保存站点 ID、Key 记录 ID、分组 ID 与脱敏标签。
- API 基址、平台、倍率和 Key 分组得到的唯一候选必须先在“扫描关联”预览中由用户确认；同倍率、多站点、多 Key 或多分组不允许按低价猜测。
- 上游 Key 读取失败时保留上次已确认关系并标记 Key 数据过期；恢复读取后重新验证。关闭调度账号不显示为使用中，也不参与上游成本。
