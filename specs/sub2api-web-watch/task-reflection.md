# Sub2API Web Watch 任务反思

## 结果

只读垂直切片已按 v2 重构为“智能运营”菜单目录，运营概览和聚合排价均回到官方 AppLayout；本地 Docker 已更新并保持健康，交付等待用户可见验收。

## 做得好的地方

- 服务器构建始终使用临时目录和资源上限，未触碰生产数据库、价格或容器切换。
- 发现并修正了内部账号错误信息外泄和不合格候选显示为 `0` 两个边界问题。
- 记录了全量测试既有失败、Wire 低内存阻塞和前端重跑资源限制，没有将未覆盖项误报为通过。
- 用户指出割裂后，定位到 WatchView 遗漏 AppLayout，而不是把问题误判为浏览器窗口行为。
- 使用现有折叠菜单模式和旧地址重定向完成最小重构，没有改动后端与数据契约。

## 改进项

- 后续应在更大内存 CI 节点完成全量 Go、Wire 和前端组合构建。
- 真实保活、自动写价、审计回滚和可见 Web 验证仍需独立验收，不应与只读切片混合发布。
- 不满意分类：`ui_interaction`。v1 只验了页面内容与构建，没有验证它在完整后台布局中的实际呈现。
- 应用内浏览器 webview 本轮无法附着；后续恢复后应补菜单展开、子菜单切换、前进后退和窄窗口截图。
